# VCF 连冲练习 · 重构设计

> 本文回答一个问题：**VCF 练习这个功能，到底在训练什么？** 想清楚了，界面才有依据。

---

## 1. VCF 是什么

**VCF = Victory of Continuous Four（连续冲四取胜）。**

五子棋里，「四」是唯一**绝对先手**的棋形：你做出一个四，对方如果不应，你下一手就成五，
棋就结束了。所以对方的应手不是选择，而是**被迫**的 —— 而且通常只有一个点可挡。

于是出现了一条捷径：

```
我冲四  →  对方唯一应点（必须挡）
        →  我再冲四  →  对方唯一应点
        →  …  →  我成五
```

这条链的**分支因子约等于 1**。普通搜索要多算 2 层就要多 400 倍节点，
而 VCF 深 10 层可能只有几十个节点。这是五子棋里唯一「算得完」的必胜手段，
也是实战中最常用的终结技。

---

## 2. 旧版错在哪

旧版 5 道题，全部长这样：棋盘上已经摆好一条四连，玩家把第五颗子补上，通过。

四个问题，一个比一个严重：

| 问题 | 后果 |
|---|---|
| **没有对手** | 对方从不还手。没有「必须应」，就没有「强制」，VCF 的核心消失了 |
| **不是连冲** | 一步就结束，练不到「串起来」这个唯一的难点 |
| **答案写死** | VCF 的正确走法常常不唯一，硬编码答案会把对的判成错的 |
| **没有失败态** | 走错也能通过（只要碰巧成五），学不到「为什么这手不行」 |

一句话：**它教的是「补空位」，不是 VCF。**

---

## 3. 它到底在训练什么

拆开看，VCF 需要三种能力，缺一不可：

1. **看见「四」** —— 认出哪些落点能让四颗子连成一线，且只剩一个成五点。
   这是纯模式识别，靠刷题量堆出来。
2. **算出「唯一应点」** —— 冲四之后对方必须挡在哪。
   算错这一步，后面的推演全是空的。
3. **串起链条** —— 这一手形成的四，被对方挡住之后，盘面上还剩不剩下一个四。
   这是最难的：**每一步都必须是四，缓一手（做成三）链条立刻断**。

所以练习的设计目标不是「让玩家答对」，而是：

> **让玩家在走错的那一刻，立刻明白「为什么这一手不行」。**

## 4. 设计推导

### 4.1 判定标准 = VCF 的定义本身

不去比对答案，而是逐步验证 VCF 的定义：

```
玩家落子
  ├─ 已成五 ─────────────────────────→ 胜
  └─ 数「补成五的点」（Kill.fivePoints）
        ├─ 0 个 → 这手不是四，对方不必应 → 判错，棋子撤回
        ├─ 1 个 → 标准冲四，对方被迫挡在该点 → 自动落白子，继续
        └─ ≥2 个 → 活四 / 双四，对方挡不住 → 胜
```

这样带来三个好处：

- **任意一条成立的连冲线都算对**（VCF 本来就不唯一）；
- 不需要维护标准答案，题库只有题面；
- 判定逻辑本身就是最好的教学：它精确地告诉你「错在第几手、错在哪」。

### 4.2 对手必须真的还手

冲四成立后，模块自动把白子落在唯一应点上 —— 不是装饰，是判定的一部分：
**下一手必须建立在「对方已经挡了」之后的盘面上。** 没有这一步，第三手就没意义。

### 4.3 走死了要立刻说

对方应手之后，用 `Kill.vcf` 复核「黑方还有没有连冲」。
没有 → 这条线走死了，立刻判失败。而不是让玩家继续乱下。

### 4.4 题库必须被证明有解

题库由 `tools/gen-vcf.js` 用引擎**反向生成**：随机撒子 → `Kill.vcf` 必须找到连冲 →
顺着必胜线走一遍，得到真实深度 → 只保留子力均衡、局面集中的。

`tests/engine/vcf-practice.test.js` 再逐题复验 68 项，其中最关键的一条是：

> **每道题标注的 `depth` 必须等于引擎实际算出的连冲手数。**

难度不是写上去的标签，是算出来的。

## 5. 界面为什么这样设计

| 元素 | 为什么 |
|---|---|
| 题目按难度分组，标注「N 手」 | 玩家能预判这题要算多深，选自己能承受的 |
| 进度条 = 已走手数 / 目标手数 | 连冲是「往前走」的过程，进度感比分数更有驱动力 |
| 走错立刻红字 + 棋子撤回 | 错的那一手不能留在盘上，否则玩家会基于错误盘面继续推演 |
| 「不是冲四」的具体解释 | 告诉玩家「对方不必应」，而不是干巴巴的「错误」 |
| 冲四成功时报出应点坐标 | 强化「唯一应点」这个关键概念 |
| 悔一步 = 撤一个完整回合 | 撤到我方落子前，否则撤完还停在对方挡完的局面，等于没悔 |
| 看答案 = 逐步演示 | 直接给终局图学不到东西，要看着链条一步步长出来 |
| 成绩只记最快 | 熟练度指标，避免刷次数 |

## 6. 与主流题库的关系

日本连珠界的「詰め連珠」、国内爱五子棋的习题库，本质都是这个结构：
**固定局面 + 轮到黑走 + 存在强制胜 + 分难度**。

本模块对齐了这套结构，区别在于判定完全由引擎完成，因此：

- 玩家走非标准但成立的线，不会被误判；
- 新增题目只要题面正确，无需人工写答案；
- 难度由引擎实测深度决定，不会标错。

## 7. 后续可扩展

- **VCT（连续活三胜）**：判定从「必须是四」放宽到「四或活三」，搜索空间大一个量级，
  需要限制深度并在 UI 上区分题型。
- **限时挑战**：同一题限时，考验模式识别速度。
- **每日一题**：按日期从题库取题，配连胜记录。
- **错题本**：记录玩家走错的那一手，事后复盘「当时为什么不是四」。
